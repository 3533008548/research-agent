### 核心结论（后续改造时复用）
- ARS 是**提示词 + 文件系统**的 skill，编排靠模型自觉遵守；本仓库是**代码编排**（LangGraph + SQLite）。
  迁移 ARS 机制时应下沉为代码约束，不要照搬提示词铁律。
- 本仓库工程保障（持久化/取消/并发/用量/熔断/RAG 降级/PDF 索引校验）强于 ARS，不要为了对齐而丢弃。
- 三大缺口：① 无研究问题收敛阶段（ARS 用 FINER + Scope + Socratic 非生成模式，且强制前置）；
  ② 判重只靠 title_similarity >= 0.88，未用 DOI/arXiv ID 做主键（paper_records.py 已有 normalize_doi/normalize_arxiv_id）；
  ③ 证据锚点实际多为 {"kind":"tool_result"} 弱定位，无引用存在性校验（ARS 有三层校验 + FABRICATED 判定）。
- 可低成本直接移植：WHY/HOW/WHAT 三段式抽取模板、Phase Boundary 越界禁令条款、
  「无法确认存在的引用 = FAIL」IRON RULE、双层引用发射 `<!--ref:En--><!--anchor:page:N-->`。
- 需重构：RQ 收敛阶段、引用存在性校验层、Claim Intent Manifest + 审计侧 drift diff、
  research_run passport 化（content_hash / version_label / 只追加账本 / pending_decision）、失败路径注册表。
